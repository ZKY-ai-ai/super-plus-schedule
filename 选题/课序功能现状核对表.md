# 课序功能现状核对表

核对日期：2026-11-16。核对基准：`main` 分支提交 `43f02ab`（工作区另有未跟踪的 `.qoder-worktrees/`，与本表无关）。

## 一、核对方法与口径

依据顺序：源码实现 → 界面入口是否接线（`App.tsx` 页面路由、设置页 tab、按钮）→ 单元测试 → `pnpm test` 与 `pnpm build`。

- 全量测试：30 个测试文件、347 项用例全部通过。
- 类型检查与构建：`pnpm build` 通过（仅剩 chunk 体积提示，不影响产物）。
- 本表不把"代码存在"等同于"真实环境已验证"，依赖真机、账号或外部服务的项目单列在第四节。

状态定义：

| 状态 | 含义 |
|---|---|
| 已实现 | 核心行为覆盖功能描述，且能从界面或已导出 API 实际使用 |
| 部分 | 主链路可用，但缺关键子能力，或入口只覆盖一种场景 |
| 未实现 | 找不到可调用实现，或只有辅助函数、类型声明、文档 |

## 六、结论

1. 129 项里 66 项已真正落地，28 项主链路可用，功能面已经不是"空底座"。
2. 最明显的体验缺口不在功能数量，而在入口位置：任务、考试、成绩目前只挂在设置页的 tab 里，日程页没有聚合，导致"有功能但找不到"。
3. 提醒、系统日历、Google 日历、截图识课、WebDAV 这五块必须先补真机或真实账号验证，否则不能对用户宣布"已完成"。
4. 剩余 35 项中只有约 10 项适合当前阶段继续做；其余依赖校内数据、多用户后端或平台生态，建议明确列为"需外部条件"。
